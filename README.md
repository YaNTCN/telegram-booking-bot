# telegram-booking-bot

Telegram-бот для записи клиентов: салон, барбершоп, студия, клиника, репетитор. Клиент сам выбирает услугу, мастера и свободное время, при желании оплачивает онлайн. Администратор сразу получает уведомление, а все записи появляются в Google Таблице.

Это демо: салон и мастера выдуманы, оплата тестовая, записи удаляются сами через сутки.

## Что получает владелец

- **Клиенты записываются сами, круглосуточно.** Бот показывает только реально свободное время с учётом длительности услуги и графика каждого мастера.
- **Видно всё сразу.** Дни и часы окрашены: зелёное свободно, красное занято или выходной, прошедшее время неактивно.
- **Постоянным клиентам быстрее.** Бот помнит прошлую услугу и мастера (они отмечены ⭐), а имя и телефон предлагает кнопками из прошлых записей. Удобно, когда клиентка записывает и себя, и подругу.
- **Двойной записи не бывает.** Если двое выбрали одно время, второй увидит, что его уже заняли, и выберет другое.
- **Предоплата.** Онлайн-оплата картой через ЮKassa прямо в Telegram. Неоплаченная бронь держит время 15 минут, потом освобождает его для других.
- **Возврат денег при отмене.** Клиент отменил оплаченную запись или её отменил салон: бот сам возвращает деньги на карту через ЮKassa. Сколько вернуть при отмене клиентом, задаётся в процентах. Если возврат не прошёл, админ получает номер платежа и может повторить его командой `/refund`.
- **Все записи в Google Таблице.** Её можно открыть с телефона, отфильтровать, выгрузить. Отмена или оплата сразу меняет статус в строке.
- **Уведомления администратору** о каждой новой записи, оплате и отмене. Отменить запись можно кнопкой прямо из уведомления, клиент получит сообщение.
- **Меньше неявок.** Клиенту приходит напоминание за день, а отменить запись он может сам, не позже чем за 2 часа.
- **Услуги, цены, мастера и график** лежат в одном файле, код менять не нужно.

## Что можно добавить под ваш бизнес

В демо есть то, что нужно почти всем. Остальное собирается как конструктор: выбираете нужное, лишнее не включаем. Каждый пункт можно добавить отдельно.

### Мастер

- Новые записи, переносы и отмены приходят мастеру в личные сообщения.
- Утром мастер получает расписание на день, вечером — на завтра.
- Мастер отмечает «клиент пришёл» или «не пришёл», а в конце недели видит итоги: сколько клиентов обслужил, сколько неявок, сколько заработал.
- Мастер сам закрывает время: перерыв, отпуск, больничный. Клиенты это время не увидят.
- Портфолио: фото работ мастера при выборе мастера.

### Администратор (рецепция)

- Запись клиента из живой очереди или по телефону за пару нажатий. Запись сразу появляется у мастера и в таблице.
- Журнал на день по всем мастерам в одном сообщении. Перенос и отмена записи с уведомлением клиента и мастера.
- Лист ожидания: если на нужное время всё занято, клиент встаёт в очередь, и бот сам предложит ему освободившееся окно.
- Несколько администраторов, у каждого свои права.

### Владелец

- Сводка каждый вечер: сколько записей, выручка, кто из мастеров загружен, кто простаивает.
- Статистика за любой период: популярные услуги, доля отмен и неявок, новые и постоянные клиенты, средний чек.
- Выгрузка в Excel для бухгалтерии.
- Сообщение владельцу, если бот перестал работать: о сбое вы узнаете раньше клиентов.

### Клиент

- «Записаться как в прошлый раз» одной кнопкой.
- Перенос записи без звонка в салон.
- Несколько услуг подряд за один визит (например, стрижка и окрашивание), бот сам подберёт время.
- Запись на групповые занятия с лимитом мест: для студий, школ, фитнеса.
- Предоплата частью (депозит), подарочные сертификаты, чаевые мастеру.
- Оценка после визита. Довольных клиентов бот попросит оставить отзыв на картах, а о недовольных сразу сообщит владельцу.

### Возвращение клиентов

- «Пора повторить»: бот знает, как часто клиент приходит, и предлагает записаться, когда подходит срок. Кнопка «не напоминать» есть всегда.
- Бонусы: например, каждый шестой визит со скидкой. Счётчик визитов виден в профиле.
- «Приведи подругу»: скидка обеим.
- «Давно не были»: одно мягкое сообщение клиенту, который пропал на два месяца.
- Новости и акции только тем, кто сам согласился их получать.

### Интеграции

- Google Календарь мастера: записи появляются в его телефоне.
- amoCRM, Битрикс24, YCLIENTS: если салон уже ими пользуется, бот работает поверх них.
- Мини-приложение в Telegram с календарём и фото услуг вместо кнопок.
- Несколько филиалов в одном боте, выбор филиала первым шагом.

Рассылки, бонусы и напоминания «пора повторить» делаются только с согласия клиента: так требует закон о рекламе и о персональных данных, и так Telegram не заблокирует бота за спам.

## Попробовать у себя

Нужен только токен бота, остальное подключается по желанию.

1. В [@BotFather](https://t.me/BotFather) отправьте `/newbot` и скопируйте токен.
2. Скопируйте `.env.example` в `.env` и впишите `BOT_TOKEN`. Чтобы получать уведомления, впишите свой Telegram ID в `ADMIN_CHAT_ID` (его покажет, например, [@userinfobot](https://t.me/userinfobot)).
3. Запустите:

```bash
docker compose up -d --build
```

Без Docker (Python 3.11+):

```bash
pip install -r requirements.txt
python -m bot
```

### Тестовая оплата (ЮKassa)

1. В @BotFather: `/mybots` → ваш бот → Payments → ЮKassa → «Connect ЮKassa: Test».
2. Бот ЮKassa проведёт через подключение, после этого BotFather покажет токен вида `123456:TEST:...`.
3. Впишите его в `PAYMENT_TOKEN`. Договор, ИП и проверка профиля в ЮKassa для тестового режима не нужны, деньги не списываются. Тестовый токен содержит `:TEST:`. Токен с `:LIVE:` не заработает, пока ЮKassa не одобрит магазин (ошибка `PAYMENT_PROVIDER_INVALID`). При запуске бот пишет в лог, какая оплата подключена.

Бот подсказывает тестовую карту при оплате (`5555 5555 5555 4477`, срок и CVC любые). Если ЮKassa её не примет, актуальные тестовые карты есть в документации ЮKassa.

### Возврат денег при отмене (ЮKassa)

У Telegram нет метода возврата для оплаты картой, деньги возвращает ЮKassa по своему API. Бот хранит номер платежа из успешной оплаты и при отмене отправляет по нему возврат.

1. В кабинете ЮKassa откройте тестовый магазин, который подключали в BotFather: «Интеграция» → «Ключи API».
2. Впишите `shopId` в `YOOKASSA_SHOP_ID`, секретный ключ (`test_...`) в `YOOKASSA_SECRET_KEY`. Это не тот же токен, что `PAYMENT_TOKEN`: тот выдаёт BotFather, этот ЮKassa.
3. `REFUND_PERCENT` задаёт, сколько вернуть, если клиент отменил сам (по умолчанию 100, `0` = не возвращать). Если отменил салон, возврат всегда полный. Клиент видит сумму возврата перед подтверждением отмены.

Без ключей отмена работает как раньше, а админ получает напоминание вернуть деньги вручную с номером платежа. Если ЮKassa не ответила или отказала, бот пишет админу причину, и возврат можно повторить: `/refund 12` (всю сумму) или `/refund 12 1500`. Повтор с теми же параметрами не вернёт деньги дважды: запрос идёт с ключом идемпотентности.

Для настоящих платежей владелец бизнеса заключает договор с ЮKassa и получает боевой токен. Код менять не нужно, только `PAYMENT_TOKEN`. Онлайн-оплата через провайдера разрешена в Telegram для физических товаров и офлайн-услуг. Цифровые товары Telegram разрешает продавать только за Stars.

### Google Таблица

Это бесплатно, банковская карта не нужна.

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) и создайте проект. Предложение «Start free trial» можно закрыть.
2. «APIs & Services» → «Library» → найдите **Google Sheets API** → «Enable».
3. «APIs & Services» → «Credentials» → «Create credentials» → «Service account». Введите любое имя, остальные шаги можно пропустить.
4. Откройте созданный аккаунт → «Keys» → «Add key» → «Create new key» → JSON. Скачается файл ключа: храните его как пароль и не публикуйте.
5. Создайте Google Таблицу и нажмите «Поделиться». Добавьте почту сервисного аккаунта (вида `...@...iam.gserviceaccount.com`) с правом «Редактор».
6. В `.env` укажите путь к файлу ключа в `GOOGLE_CREDENTIALS` и ID таблицы в `SPREADSHEET_ID`. ID — это часть адреса между `/d/` и `/edit`.

Шапку таблицы бот создаст сам. Если Google недоступен, запись всё равно сохраняется в боте, а ошибка пишется в лог.

### Свой салон

Отредактируйте `data/salon.json`: название, услуги (длительность и цена), мастера, какие услуги они делают и график по дням недели (1 = понедельник). Там же шаг сетки, минимальное время до записи и на сколько дней вперёд можно записываться.

## Как устроено

| Что | Где |
|---|---|
| Шаги записи в одном сообщении, «« Назад» на каждом шаге | `bot/handlers/booking.py` |
| Расчёт свободного времени и раскраска дней и часов (чистые функции) | `bot/slots.py`, `bot/keyboards.py` |
| Память: прошлая услуга и мастер, до 3 последних имён и телефонов кнопками | `bot/storage.py`, `bot/handlers/booking.py` |
| Защита от двойной записи: проверка и вставка под одной блокировкой | `bot/storage.py` |
| Неоплаченная бронь держит время ограниченный срок | `bot/storage.py`, `bot/jobs.py` |
| Оплата: проверка брони перед списанием (pre_checkout) и после | `bot/handlers/payments.py` |
| «Мои записи» и отмена с подтверждением и ограничением по времени | `bot/handlers/my_bookings.py` |
| Возврат денег через API ЮKassa при отмене оплаченной записи | `bot/refunds.py`, `bot/services.py` |
| Админ: записи на день (`/day`, `/day 05.12`), отмена из уведомления, повтор возврата (`/refund 12`) | `bot/handlers/admin.py` |
| Google Таблица в отдельном потоке, её сбой не ломает запись | `bot/sheets.py` |
| Напоминания, снятие неоплаченных броней, автоудаление демо-данных | `bot/jobs.py` |
| Кнопки меню работают на любом шаге, устаревшие кнопки отвечают подсказкой | `bot/app.py`, `bot/handlers/common.py` |

Тесты (`pytest`) гоняют настоящий `Dispatcher` с подменённым Telegram и часами: полный путь записи, гонка двух клиентов за одно время, оплата, истечение брони, отмены и возвраты (с локальным сервером вместо API ЮKassa), напоминания, удаление демо-данных, таблица.

```bash
pip install -r requirements-dev.txt
pytest
```

## Персональные данные

В демо бот просит вводить выдуманные имя и телефон и сам удаляет записи через `DEMO_TTL_HOURS` часов, из таблицы тоже. В рабочем боте оператором данных клиентов будет владелец бизнеса: ему нужны политика обработки персональных данных и согласие клиента. Шаг «согласен на обработку данных» со ссылкой на политику добавляется по запросу.
